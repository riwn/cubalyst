# データの読み方と目安

## 単一ソルブ（get_solve）

| 部分 | 見るところ |
|---|---|
| 冒頭 | タイム、手数、TPS、持ち方（解法の表記はこの持ち方での面の名前）。スクランブルだけは白上・緑前 |
| 段階ごと | 段階ごとの「所要＝認識＋実行」、手数、実行の TPS、その段階の解法 |
| 長い間 | 手と手の間隔の上位。どの段階の何手目かが分かる。F2L の途中に集まっていればルックアヘッド、OLL や PLL の途中なら 2-look の継ぎ目や手順の思い出し |
| 面ごとの回転数 | 偏り。B や D が多いのは、持ち替えずに回しているか、持ち替えが記録に出ていない可能性 |
| 直近の平均との比較 | このソルブだけ遅いのか、いつも遅いのか。ばらつき（SD）が大きい段階は安定していない |

- 「認識」は、その段階の最初の手までの待ち時間（直前の段階の終わりから）。Cross の認識は 0（インスペクション中に見ている）
- 180度回転は 2手（`R2` → `R R`）で数える。手数は一般的な数え方（HTM）より多めに出る
- 「解法」の列は、同じ面の続きをまとめた表記（`R R` → `R2`、`R R R` → `R'`、`R R'` は打ち消して消える）。そのため、列の記号の数は「手数」より少ないのが普通
  - 手数と比べるときは、列の `R2` を 2手、それ以外を 1手として数える。それでも手数のほうが多ければ、その差は打ち消しで消えた手（回して戻した、迷って行き来した）。無駄な手の目安になる
  - `R'` が実際は `R R R` と回されていた場合も差が出るが、まれ
- 向かい合う面が交互・続けて回る並び（例 `F B' F B'`）は、M などのスライスムーブの可能性が高い。手数が多く見えても、実際の動きは少ないことがある
- OLL の途中に 1秒前後の間がある、または OLL の手数が 15手を超える → 2-look OLL の可能性。PLL も同様

## まとめ（get_solves）

| 部分 | 見るところ |
|---|---|
| タイム | 平均・中央値・ベスト・ワースト・SD、ao5 / ao12 の今とベスト |
| 段階別の平均 | どの段階が全体の何割か。認識と実行の比 |
| 前半と後半 | 件数が 10件以上のときだけ出る。どの段階が縮んだか、伸びたか |
| 最も時間を使った段階 | ほとんどのソルブで F2L になるのは普通。Cross や PLL が上位に来るなら要注意 |
| ケース別 | 手順練習（mode=case）のときだけ。平均が遅い順 |

件数が少ない（10件未満）ときは、傾向として断定しない。

## レベルの目安（フルソルブの平均）

あくまで目安。本人の平均から今の段階を見て、その段階で効く助言を選ぶ。

| 平均 | よくある姿 | 効きやすい助言 |
|---|---|---|
| 60秒以上 | 初心者法や 2-look。F2L の1ペアごとに長く止まる | F2L の基本形（ペアを作って入れる）を覚える。手順を正確に回す |
| 30〜60秒 | 直感 F2L、2-look OLL / PLL | F2L の止まりを減らす（ゆっくり止まらずに回す）。PLL をフルで覚える（21個）|
| 20〜30秒 | フル PLL、OLL は一部 | F2L のルックアヘッド、Cross を 8手以内で計画。OLL を増やす |
| 20秒未満 | フル OLL / PLL | F2L の効率（手数）、TPS、Cross+1 の計画 |

段階の比率のおおよその目安（平均 20〜60秒の人）：

- Cross：全体の 1〜2割、6〜8手（180度を2手で数えるとそれより多め）
- F2L：全体の 5〜6割。1ペアあたり 8〜12手。ペアの間の「認識」が実行より長ければ、ルックアヘッドが伸びしろ
- OLL / PLL：それぞれ全体の 1〜2割。認識が 1秒を超えるなら、ケースの見分けが伸びしろ

## 書くときの注意

- 数字は入力にあるものだけを使う。計算した値（比率・差）は計算したと分かるように書く
- 秒は小数第2位まで
- 持ち替えや指の使い方は記録から見えない。言うなら「〜の可能性」とする
